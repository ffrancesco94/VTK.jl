# Architecture & layering

VTK.jl has three layers. Knowing where a piece lives explains most design
decisions — and most error messages.

```
┌────────────────────────────────────────────────────────┐
│ Julian layer (src/*.jl)                                 │
│   typed wrappers, iterators, do-the-right-thing helpers │
├────────────────────────────────────────────────────────┤
│ C++ binding module (libvtk_julia.so)                    │
│   WrapIt-generated code + automatic and hand-written    │
│   shims: CxxWrap types, methods, and factories          │
├────────────────────────────────────────────────────────┤
│ VTK 9.7 (VTK_jll artifacts)                             │
│   libvtkCommon*, libvtkFilters*, libvtkIOXML, ...       │
└────────────────────────────────────────────────────────┘
```

## The C++ binding module

The C++ surface is generated from VTK headers by
[WrapIt](https://github.com/grasph/wrapit) and compiled into one merged
`libvtk_julia.so` with two companion shims:

- **WrapIt-generated bindings** register the bulk of the classes, inheritance,
  and methods. The post-processing step repairs hierarchy edges WrapIt cannot
  infer, so Julia subtype conversion mirrors VTK up-casts. Concrete AOS arrays
  (`vtkFloatArray`, …) are registered beneath `vtkDataArray`.
- **The automatic shim** (`gen/wrapit/auto_shim.jl` → `shim_auto.cpp`) adds
  owning `X_new` factories and accessors declared through VTK macros.
- **The hand-written shim** (`gen/wrapit/shim_vtkjl.cpp`) handles behavior that
  requires a human decision: smart-pointer ownership, generic algorithm input
  and output, downcasts, error capture, and zero-copy workers.

Factories and owning getters return `vtkSmartPointer<T>`. CxxWrap's custom
smart-pointer traits ensure that Julia holds a real VTK reference and releases
it when the Julia object is finalized. Methods generally accept raw `T*`
pointers; the Julia forwarding layer described below makes ordinary calls work
directly with smart pointers.

By default, VTK.jl loads the merged library from `VTK_julia_jll`. To build a
local development version against the VTK artifacts, run:

```sh
julia --project=. gen/build_wrapper.jl
```

Set `VTKJL_LIB` to the resulting library to use it instead of the JLL. Clear
VTK.jl's precompile cache when switching libraries, because that cache does not
track `VTKJL_LIB` or changes to the shared library's contents. See [The WrapIt
driver](wrapit.md) for the complete generation pipeline.

## The Julian layer

`src/*.jl` turns the raw surface into something pleasant:

| file | contents |
|---|---|
| `dataarray.jl` | untyped array helpers: `raw_data`/`data` zero-copy views, names, resize |
| `typedarray.jl` | `VTKDataArray{T}`: typed `AbstractMatrix` wrapper with cached view + scalar-type discovery |
| `dataset.jl` | grid construction, field-data access, XML I/O |
| `cells.jl` | cell registry/iterators, `MeshCell` converters, `UnstructuredGrid(points, cells)` |
| `filters.jl` | `update!`, implicit functions, the filter functions |

The package exports **nothing** on purpose: all names are used qualified
(`VTK.read_vtu`), which avoids collisions with VTKBase/WriteVTK/ReadVTK in
the same session.

## Generated smart-pointer overloads

C++ methods are registered with raw-pointer arguments. The build reads those
registrations and generates `src/generated_methods.jl`, which adds Julia
overloads accepting CxxWrap smart pointers. Each overload converts its VTK
arguments via:

```julia
_cp(::Type{T}, x) where {T} = CxxPtr{T}(x[])   # CxxPtr of static type T
```

and calls the original raw-pointer method. Generic base-class shim APIs also
get hierarchy-independent fallbacks for classes whose Julia parent chain is
incomplete. Thus ordinary code is simply `SetInputData(filter, grid)` or
`Update(reader)`, with no hand-written cast. The original methods remain
available as `Update(_cp(vtkAlgorithm, reader))` for low-level use.

Why not register by-value smart-pointer arguments? CxxWrap's by-value
smart-pointer path dispatches on `Type{Dereferenced{T}}`, and Julia's
`Type` is *invariant* — the dispatch is impossible to hit for custom smart
pointers. Raw pointers plus generated forwarding overloads sidestep this.
This is recorded as design debt §4.2 in `STATUS.md`.

## Errors

VTK routes its output window into a buffer at module init. Every
high-level call (`clip`, `slice`, `read_vtu`, …) ends in `update!`, which
throws with VTK's message if anything was reported — so a failing pipeline
raises instead of returning half-baked data.

## Generated sources

Both `shim_auto.cpp` and `src/generated_methods.jl` are regenerated by the
wrapper build. Edit their generators or the hand-written shim—not the generated
artifacts—when changing the bindings. The low-level integration test and the
main package suite then verify the rebuilt library at the CxxWrap and high-level
Julia layers, respectively.
