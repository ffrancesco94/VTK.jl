# VTK.jl — Status & Implementation Plan

Last updated: 2026-11-05. WrapIt migration **complete** and the legacy
hand-written CMake wrapper **removed** (2026-10-29). The WrapIt-generated +
shim-merged `libvtk_julia` now loads from `VTK_julia_jll` by default;
`VTKJL_LIB` remains available for local development builds. CI exercises the
JLL on Julia 1.11–1.13 without requiring a C++ toolchain. Durable gotchas live
in `AGENTS.md`.

## 1. Goal

Julia bindings for a CFD-oriented subset of VTK 9.7: data model, XML I/O, and
manipulation filters (clip, slice, cell↔point conversion, contour, surface
extraction). No rendering, no MPI-aware API. Long-term: a maintainable
binding-generation pipeline (WrapIt + shim) and an idiomatic "Julian" layer
on top of the raw bindings.

## 2. Current state (what works)

Binary/runtime foundations:

- `VTK_jll` 9.7.1 provides full headers, `lib/cmake/vtk-9.7` configs, and the
  `vtkWrap*` tools; we build our binding module against it. No local VTK
  build needed.
- Binding generation: the **default build is the WrapIt driver**
  (`gen/build_wrapper.jl` → `gen/wrapit/build.jl`): it builds **wrapit from
  source** ([`ffrancesco94/wrapit`](https://github.com/ffrancesco94/wrapit),
  containing the validated Bug-1 macro-truncation fix, PR #1 — no
  `WrapIt_jll`, no veto loop), generates the CxxWrap bindings from VTK
  headers, merges the hand shim + auto-shim, and installs the result at
  `wrapper/build/libvtk_julia.so`. Requires git, CMake, a C++17 compiler,
  libclang + OpenSSL dev headers. Gotcha: the precompile cache does not
  track `VTKJL_LIB` — clear `~/.julia/compiled/v1.*/VTK` when switching.
- Generated surface: **72 classes registered, ~3,150 generated methods** +
  25 auto-shim methods (18 classes) + ~90 hand-shim methods, all in one
  library. The auto-shim (`gen/wrapit/auto_shim.jl` → `shim_auto.cpp`)
  derives owning `X_new` factories and macro accessors (`vtkSetMacro`,
  `vtkBooleanMacro`, …) from the VTK headers textually — these are invisible
  to libclang because they only exist after the C preprocessor runs; 282
  more were skipped because WrapIt already emitted them. A single generic
  `SetInputData`/`GetOutput` on `vtkAlgorithm` covers all
  readers/writers/filters (downcasts in the Julian layer), so adding a class
  usually needs no shim edits. Hand-written remainder (`shim_vtkjl.cpp`,
  ~460 lines): ownership policy, error window, zero-copy workers, downcasts,
  up-casts, convenience adapters.
- Self-healing clash vetoes: when the shim and WrapIt would register the same
  method, `veto_shim_clashes!()` mechanically adds the generated overload to
  `veto.txt` (11 hand-maintained lines + ~65 auto-derived) and regenerates
  until converged.
- Upstream engagement: WrapIt bug reports + validated patches (Bug-1 merged
  as `ffrancesco94/wrapit#1`); local patches live in `docs/patches/`.
- MPI: VTK_jll is an MPI-enabled build; `libmpi` (MPICH/OpenMPI/MPIABI
  flavor) is pre-loaded in `VTK.jl` before the wrapper library is dlopened.
- Ownership: all factories/outputs return `vtkSmartPointer{T}` registered via
  CxxWrap's custom smart-pointer traits (`IsSmartPointerType`,
  `ConstructorPointerType`). Julia finalizers drive `UnRegister`; GC-stress
  tests pass.

Wrapped surface (generated by the WrapIt driver + merged shim):

- `vtkDataArray` family: abstract API (components, tuples, names, resize),
  factories for Float32/Float64/Int32 plus a **generic typed factory**
  `data_array(T, ncomp)` covering all of VTK's scalar types via
  `vtkAbstractArray::CreateArray`, **zero-copy views** via
  `vtkArrayDispatch` → `GetVoidPointer` → CxxWrap `make_julia_array`
  (AOS-only, mirroring VTK's own buffer-protocol caveat). Views are created
  directly at the target dimensionality (flat vector or `(ncomp, ntuples)`
  matrix) as plain `Array`s; `create_if_not_exists<ArrayRef{V,2}>` is needed
  since CxxWrap pre-registers only 1-D array wrapper types.
- Data model: `vtkPoints`, `vtkUnstructuredGrid`, `vtkPolyData`,
  `vtkImageData` (types registered with true VTK inheritance; construction
  currently exposed for unstructured grids), field data (`vtkPointData`/
  `vtkCellData`) with `AddArray`/`GetArray`/`SetActiveScalars`.
- I/O: `vtkXML{UnstructuredGrid,PolyData,ImageData,RectilinearGrid,StructuredGrid}-
  {Reader,Writer}` (`.vtu/.vtp/.vti/.vtr/.vts`) plus `vtkXMLMultiBlockData-
  {Reader,Writer}` (`.vtm` containers with `block`/`set_block!`/`nblocks`);
  writers emit zlib-compressed appended data by default, or raw appended
  data (`raw_appended=true`) which ReadVTK.jl can parse.
- CFD readers: `vtkEnSightGoldReader` (`.case` + geometry),
  `vtkCGNSReader` (`.cgns`), and `vtkXMLPPolyDataReader` (`.pvtp`
  parallel summaries); all produce `vtkMultiBlockDataSet` except
  `vtkXMLPPolyDataReader` which yields `vtkPolyData`.
- Legacy I/O: `vtkGenericDataObjectReader`/`vtkGenericDataObjectWriter`
  (`.vtk` format, any dataset type), plus specific
  `vtkDataSetReader`/`Writer`, `vtkUnstructuredGridReader`/`Writer`,
  `vtkPolyDataReader`/`Writer`, `vtkStructuredGridReader`/`Writer`,
  `vtkRectilinearGridReader`/`Writer` for type-specific access.
- Filters: `vtkTableBasedClipDataSet`, `vtkCutter`, `vtkCellDataToPointData`,
  `vtkPointDataToCellData`, `vtkContourFilter`, `vtkDataSetSurfaceFilter`,
  plus `vtkPlane` implicit function.
- Type hierarchy mirrors VTK inheritance (`vtkUnstructuredGrid <: vtkPointSet
  <: vtkDataSet <: vtkDataObject`) enabling Julia-side up-cast conversions of
  smart pointers and `SafeDownCast`-based downcasts (`UnstructuredGrid(obj)`,
  `PolyData(obj)`, `ImageData(obj)`).
- Error handling: VTK's output window is redirected into a buffer;
  `update!` throws on any VTK error (used by all high-level calls).

Julian layer (`src/dataarray.jl`, `src/typedarray.jl`, `src/dataset.jl`,
`src/cells.jl`, `src/filters.jl`):

- `data(da)`/`raw_data(da)`: zero-copy `(ncomp, ntuples)` / flat views
  derived from an **owning** `VTKDataArray` wrapper ("wrapper-owns-
  everything"): the underlying array stays alive as long as any derived
  view does, even if the original handle is dropped.
- `VTKDataArray{T}`: parametric `AbstractMatrix{T}` of shape
  `(ncomp, ntuples)` holding the smart pointer (ownership), zero-copy cached
  view, typed `getindex`/`setindex!`, `resize!`; `field_array`/`points_array`
  return typed wrappers or `nothing`.
- Grid construction: `Points()`, `UnstructuredGrid()`, `pts[i] = (x,y,z)`,
  `insert_cell!` (accepts raw ids or `VTKCellTypes.VTKCellType`),
  `set_points!`, `allocate!`; `UnstructuredGrid(points, cells)` from a 3×n
  matrix + `MeshCell` vector.
- `read_vtu`/`read_vtp`/`read_vti`/`read_vtr`/`read_vts`,
  `write_vtu`/`write_vtp`/`write_vti`/`write_vtr`/`write_vts`, `field_array`,
  `point_data`, `cell_data`, `activate_point_data!`.
- CFD readers: `read_ensight` (EnSight Gold `.case`),
  `read_cgns` (CGNS `.cgns`), `read_pvtp` (parallel PVTK `.pvtp`).
- Legacy I/O: `read_legacy_vtk` (any `.vtk` dataset type, returns downcast),
  `write_legacy_vtk` (any dataset, format chosen automatically).
- Generic name-based `downcast(obj)` dispatching on the VTK dynamic class
  name via `GetClassName` and a registry (`DOWNCAST_REGISTRY`); adding a
  grid type = one registry entry + its `downcast_foo` shim binding.
- Cell/point access: `cell_type`/`cell`/`cells`/`eachcell` (VTKBase
  `MeshCell`, 1-based connectivity), `eachpoint`, `coordinates` (zero-copy
  typed 3×n view). Cell vocabulary comes from VTKBase (`VTKCellTypes`), the
  shared registry of ReadVTK/WriteVTK — `cells(grid)` is directly consumable
  by `WriteVTK.vtk_grid`.
- `plane`, `clip`, `slice`, `cell_to_point`, `point_to_cell`, `contour`,
  `extract_surface`, `calculator`, `gradient`, `threshold`, `stream_tracer`,
  `particle_tracer`, `line_source`, `sample_over_line`, `update!` — filters
  generated by `@vtk_filter` or hand-written for multi-input cases.

## 3. Test suite (181 tests, all passing)

- **Array core**: typed creation, zero-copy write-through both directions,
  multi-component reshape, names, Int32 element type, GC churn with
  survivors.
- **Typed wrapper**: type-stable indexing, value round-trips through the
  typed API, zero-copy visibility, resize invalidation, type mismatches
  rejected, discovery from untyped factories.
- **Cells/iterators/converters**: VTKBase registry ids and names, 1-based
  connectivity, `eachcell`/`eachpoint`/`coordinates`, round-trip
  `UnstructuredGrid(coordinates, cells)` reconstruction, WriteVTK writes our
  mesh description and our reader reads it back.
- **Views vs GC**: views obtained via `data`/`raw_data` survive collection
  of the owner (wrapper, array, or entire grid) — dropping the last owner
  reference is safe under aggressive `GC.gc()` churn, through the untyped
  API, the typed wrapper, and grid field arrays.
- **Analytic oracles**: clip of unit hex against plane x+y+z=1 (inside-out)
  yields exactly the tetrahedron (1 cell, 4 points, max coordinate sum 1.0);
  default clip side verified as complement; constant-field c2p stays
  constant; linear-field p2c averages to 1.5 on a unit hex; slice at x=0.5
  gives the unit square; contour points lie on the isosurface; surface
  extraction preserves the 8 vertices; stream tracing a constant vector field
  through the unit hex produces an 11-point streamline.
- **Independent oracles**: our `.vtu` output verified with ReadVTK.jl (pure
  Julia); our reader verifies WriteVTK.jl output — both directions.
- **Robustness**: GC/finalizer stress across full pipelines; missing field
  names return `nothing`.
- **Auto-shim**: macro accessors
  (`InsideOutOn/Off`, `GetInsideOut`, `GetUseValueAsOffset`, `GetFileName`)
  and auto factories (`PolyData_new`).
- **Structured XML I/O**: `.vti/.vtr/.vts`
  round-trips through VTK.jl's own readers/writers, with WriteVTK.jl output
  read by VTK.jl and VTK.jl output re-read by VTK.jl (ReadVTK.jl does not
  parse zlib-compressed appended data, so the write-side oracle is limited
  to geometry/header checks); generic `downcast` dispatch on reader outputs.
- **CFD readers**: EnSight Gold `.case` with
  analytic oracle (unit hex); CGNS smoke test (reader construction +
  error on missing file); parallel `.pvtp` summary + piece files written
  by WriteVTK, read back and verified.
- **Legacy VTK I/O**: unstructured grid
  round-trip with field data (unit hex + temperature); missing-file error.

## 4. Known limitations / design debt

1. **Array interface**: zero-copy views are ownership-safe — `data`/`raw_data`
   return views derived from an OWNING `VTKDataArray` wrapper (the
   "wrapper-owns-everything" design), so the owner handle may be dropped.
   Owner-capturing finalizers on views remain forbidden: an experiment
   attaching them made C++ VTK objects die on GC finalizer threads and
   reproducibly corrupted concurrently running pipelines (~25% heisenbug
   test failures; clean with `--gcthreads=1`). Remaining caveats: after
   `resize!`, previously obtained views are invalidated by VTK
   reallocation; and the grown region is NOT zero-initialized.
2. **Argument-passing pattern**: C++ methods take raw `T*`. The generated
   Julian overloads in `src/generated_methods.jl` accept smart pointers and
   forward via `_cp(T, obj)` (`CxxPtr{T}(obj[])`), so normal callers do not
   write the conversion. CxxWrap's by-value smart-pointer argument path is
   unusable for custom smart pointers (`Type{Dereferenced{T}}` dispatch is
   impossible — Julia's `Type` is invariant). Raw-pointer overloads remain
   available for low-level code.
3. **Arrays**: no typed get/set accessors (all access goes through zero-copy
   views or the slow double-based virtual API); SOA/variant arrays
   unsupported for zero-copy (guarded, throws).
4. **I/O**: XML + CFD formats (EnSight Gold, CGNS, parallel `.pvtp`) +
   legacy `.vtk`; `.pvtu` is unwrapped. Writers only emit
   appended data for XML (fine for CFD); legacy writer emits ASCII.
   ReadVTK.jl (the pure-Julia oracle) does not parse zlib-compressed
   appended blocks, so compressed output is verified by re-reading with
   VTK.jl itself.
5. **Data model**: unstructured grids fully constructible from Julia; other
   grid types readable but not constructible. Cell types are bare integers
   (`VTK_HEXAHEDRON = 12`).
6. **Downcasts**: generic name-based `downcast(obj)` dispatches through
   `DOWNCAST_REGISTRY`, built automatically at module load from the types
   the loaded library registers + their `downcast_foo` shim bindings — no
   manual registry edit when adding a grid type (add the type + shim
   binding, rebuild; only extend `DOWNCAST_SOURCES` for a genuinely new
   kind of type). Unregistered classes raise `KeyError`.
7. **Distribution**: `VTK_julia_jll` provides the wrapper on supported
   64-bit non-Windows platforms. Other platforms require a local C++17
   toolchain and the `VTKJL_LIB` override.
8. **WrapIt upstream**: Bug 1 fixed only in our fork, with an upstream issue
   opened; Bugs 2–4 worked around in the driver (AOS post-processor,
   `export_blacklist`, ostream vetoes).
9. **Particle tracer**: `particle_tracer` is experimental and its seed input is
   a VTK algorithm, not the `PolyData` returned by `line_source`. A static-grid
   smoke test crashed inside `vtkParticleTracerBase::Execute`; no execution
   example is advertised until a temporal-pipeline test is validated.

## 5. Risks

- CxxWrap attaches `delete` finalizers to smart pointers, so C++ VTK
  objects can die on GC finalizer threads whenever Julia collects the
  wrapper; adding *more* finalizer-driven deletions (owner-capturing view
  finalizers) empirically corrupts concurrent VTK work (see §4.1). Until the
  wrapper-owns-everything redesign, avoid patterns that defer C++ object
  death into GC.
- WrapIt is pinned to our fork until the Bug-1 patch lands upstream; local
  regeneration builds it from source and therefore needs network access
  (clone + FetchContent) and a working libclang toolchain. Normal package CI
  uses the prebuilt JLL instead.
- VTK_jll has no Windows build; Windows support requires our own VTK build.
- VTK_jll's MPI flavor complicates end-user installs; escape hatch is a
  custom non-MPI VTK build (defer until requested).

### Phase 3 — Julian layer

- [x] Cell/point iterators (`cell`/`cells`/`eachcell`/`eachpoint`),
      `UnstructuredGrid(points, cells)` constructor; `cells`/`coordinates`
      interop with WriteVTK (`vtk_grid(filename, coordinates, cells)`)
- [x] Memory-management hardening, "wrapper-owns-everything" design:
      `data`/`raw_data` return views derived from an owning `VTKDataArray`
      (structural lifetime, no view finalizers; §4.1/§5)
- [x] Pass-through filters return downcast types (2026-10-28): `clip`,
      `cell_to_point`, `point_to_cell` now use `downcast(GetOutput(f))`
      instead of hard-coding `UnstructuredGrid`, so poly/structured/image
      inputs produce correctly typed outputs
- [x] **`@vtk_filter` macro** (2026-10-29): declarative filter wrapper
      generation. Each filter is a one-liner plus its filter-specific
      configuration block:

      ```julia
      @vtk_filter clip(grid, implicitfn, TableBasedClipDataSet → pass_through;
                      insideout=false) begin
          SetClipFunction(f, implicitfn)
          SetInsideOut(f, insideout)
      end
      ```

      The macro generates the standard wrapper: `Factory_new()`,
      `SetInputData`, the config block (with access to `f`, positional args,
      and kwargs), `update!`, and the appropriate output downcast. Output
      type annotations: `pass_through` (matches input), `vtkPolyData` etc.
      (fixed output), or `auto` (generic `downcast`). Eliminates ~5 lines
      of boilerplate per filter and enforces consistent error handling.
- [ ] Meshes.jl/GeometryBasics bridges — deferred (mixed-cell grids vs
      homogeneous-typed Julia meshes need a target-representation decision);
      plain `(points, cells)` data already feeds both manually
- [ ] Performance pass: typed accessors via `vtkArrayDispatch` if profiling
      demands it

### Phase 4 — packaging

- [x] `VTK_julia_jll` via BinaryBuilder (Geant4.jl pattern), used by default
